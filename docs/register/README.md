## The four lookup questions, answered

**Where is the newest entry?** Read `docs/register/LATEST.md` — line 1 is the newest version and
its summary (this is also what `tools/seat/orient.sh` prints to every incoming seat). The full
entry is `docs/register/entries/v<N>.md`; entries are one file each, highest N = newest. Never
read the record front to back.

**How do I find entry vNNN?** v622–v812: it is inside the frozen file — `grep -o '· v713 [^·]*'
docs/OPEN_ITEMS_REGISTER.md` (the frozen file is one long line 1; grep, don't open). v813+:
`docs/register/entries/vNNN.md`, directly. The generated `index.json` here maps every version to
its file.

**How do I find N32 (an N-number standing ruling)?** All N-numbers to date live in the frozen
file: `grep -o 'N32[^·]\{0,200\}' docs/OPEN_ITEMS_REGISTER.md`. New entries may add N-numbers;
`index.json`'s `nnumbers` map lists every home each N-number appears in.

**How do I find item 399 (a numbered legacy item)?** The numbered-item era is closed and frozen:
`grep -o '399\. \*\*[^*]*\*\*' docs/OPEN_ITEMS_REGISTER.md`, or `index.json`'s `items` map.

## The write procedure (replaces the pen mechanics retired from docs/CURRENT_STATE.md:393-396)

The supervisor pen is the ONLY writer (seat charter law). To pen an entry:

1. Write the entry BODY to a scratch file (no marker — the pen writes the marker).
2. `python3 tools/seat/pen.py append --entry-file <F> [--incident yes|no]`
   — computes the next version, writes `entries/vNNN.md`, rewrites `LATEST.md`, regenerates the
   address index, and runs `verify`.
3. Regenerate the generated surfaces that quote the register: `python3 tools/incident_index.py
   write` and `python3 -m tools.landing.state write` (docs/STATE.md quotes LATEST.md line 1, so
   every pen stales it — the `state_file` runner check reds until this runs; learned the measured
   way at register v821/v822).
4. Commit EXPLICIT-PATH (process law P8): the new entry file, `LATEST.md`, `INDEX.md`,
   `index.json`, `docs/incidents/INDEX.md` + `index.json`, and `docs/STATE.md`. Push.

`python3 tools/seat/pen.py verify` is the standing falsifier set: the frozen file's md5 against
the seal in `frozen_identity.json` (a moved byte is a hard fail), entry well-formedness, version
contiguity from v813, LATEST freshness, index freshness. It runs in the acceptance runner, so
drift is loud.

## What is frozen, and dispositions of record

`docs/OPEN_ITEMS_REGISTER.md` is byte-sealed (identity in `frozen_identity.json`; final entry =
the v812 tombstone). It stays at its path forever so 1,260 tree-wide citations (`register vNNN`,
`register item NNN`, N-numbers, the path itself) keep resolving. The rulings-sweep evidence tools
(`docs/evidence/rulings_sweep_2026-08-13/tools/segment_register.py`, `build_inventory.py`) are
frozen historical instruments for the frozen form — never run them against this directory.
`docs/incidents/INDEX.md` (+ `index.json`) is generated by `tools/incident_index.py` over BOTH
homes and is asserted current by the acceptance runner.
