## 5. THE GUARD MOVES INTACT — WHAT IS ASSERTED, AND WHAT IS NOT

**The kept behaviour, stated as predictions:**

- A **drifted sheet** — md5, row count or injured=Y count disagreeing with the declaration — still
  HALTS the build, with the ORDER 41 / ORDER 42 halt text byte-unchanged.
- An **absent pin file** HALTS, fail-closed, with a new `SHEET-PIN HALT`. The absent-sheet halts are
  untouched.
- **Each block keeps its OWN firing regime** (PLAN_v6 3a is explicit that unifying the halt behaviour
  would change semantics in exactly the regime P4's collapse proofs exercise). The pins are read
  INSIDE `if _O41_INJ:` and INSIDE `_o42_state`, so a dial-off build reads the pin file not at all,
  exactly as it read the literals not at all before. **ORDER 41 still halts FIRST.**
- The pin file resolves the same way the sheet does: `os.environ['RL_REPO']` + a repo-relative path.
  `staged_apply` copies the whole of `data/` into its staged workspace already, so the staged build
  reads the same declaration the checkout ships.

**Proof:** `GUARD_REGIME_PROOF.py` in this directory exercises the four dial states and the drift /
absence cases against the real module text and records the verdicts in `GUARD_REGIME_PROOF.txt`. The
board byte-identity of §2 is proved by the lander's own build, which is the stronger of the two.
