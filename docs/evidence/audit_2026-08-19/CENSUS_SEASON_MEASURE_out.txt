2 · THE CANCELLATION TEST — is cp.SEASON actually load-bearing where it appears?
--------------------------------------------------------------------------------------------------------
   _playable(p,Y)      = cp.SEASON * (seasons_elapsed + fE)          [_merged_recover.py:135]
   _playable_fse(p,Y)  = SEASON    * (seasons_elapsed + fE)          [conditional_prior.py:111]
   Both are consumed ONLY as  _playable(p,Y) / cp.SEASON  :
       _merged_recover.py:302   POLE_RAMP * min(1, _playable(p,Y)/cp.SEASON)
       conditional_prior.py:117 LEVEL_RAMP * min(1, _playable_fse(p,Y)/SEASON)

   with SEASON=18  ->  playable/SEASON at (0,1,2,5) seasons elapsed = ['0.5800', '1.5800', '3.0000', '6.0000']
   with SEASON=22  ->  playable/SEASON at (0,1,2,5) seasons elapsed = ['0.5800', '1.5800', '3.0000', '6.0000']
   with SEASON=23  ->  playable/SEASON at (0,1,2,5) seasons elapsed = ['0.5800', '1.5800', '3.0000', '6.0000']
   with SEASON=26  ->  playable/SEASON at (0,1,2,5) seasons elapsed = ['0.5800', '1.5800', '3.0000', '6.0000']

   VERDICT: the ratio is IDENTICALLY (seasons_elapsed + fE) for every value of SEASON.
   cp.SEASON CANCELS EXACTLY at both sites. Changing 22 -> 18 there changes NOTHING.
   The live bars at those two sites are POLE_RAMP=22.0 and LEVEL_RAMP=14.0, which are GAMES bars,
   not season-length constants — and LEVEL_RAMP is ALREADY 14.
